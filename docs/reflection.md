# KijaniKiosk DevOps Capstone Reflection

## Reflection

The KijaniKiosk DevOps capstone gave me practical experience in designing and validating an end-to-end delivery workflow rather than focusing only on application deployment. The strongest lesson from the project was that a successful DevOps solution depends on the relationship between infrastructure, configuration, automated validation, deployment controls, observability, and recovery.

I used Terraform to provision the staging Kubernetes namespace and Ansible to manage environment-specific configuration. This separation helped me understand the difference between infrastructure provisioning and configuration management. It also made the staging and production environments easier to reason about because the same Kubernetes Deployment manifest could be reused while ConfigMaps and Secrets supplied different environment values.

The Jenkins pipeline was one of the most important parts of the capstone. I implemented a staging-first flow that performs CI checks, infrastructure validation, Ansible configuration, staging deployment, smoke testing, error-rate monitoring, and a manual production approval before production deployment. During the final audit I identified that Jenkins was validating an older Week 5 source directory instead of the final receipt-capable payments application. I corrected the Jenkins working directory to `deployment-pipeline/containers` and reran the pipeline. The final Jenkins build completed successfully while testing the same application source represented by the deployed `v1.2.0` image. This reinforced the importance of traceability between source code, CI validation, container images, and deployed artifacts.

Security and monitoring also became practical rather than theoretical. The pipeline enforces `npm audit --audit-level=high`, and dependency vulnerabilities discovered during development were remediated instead of ignored. The staging monitoring gate performs live health probes and blocks promotion when the error rate is greater than five percent. The final pipeline completed with a healthy staging result before the manual approval stage. I also demonstrated deployment failure and recovery using Kubernetes rollout history and rollback to a known-good image.

The AWS receipt chain extended the project beyond a traditional CI/CD exercise. A successful staging payment publishes a receipt to S3, which triggers a Receipt Processor Lambda, writes a processed record, invokes a Notifier Lambda, and produces a notification record. I verified the same receipt ID across the payment service, S3 objects, and CloudWatch logs. Production intentionally leaves `RECEIPTS_BUCKET` unset, so the same `v1.2.0` image can run in both environments without enabling the staging-only receipt integration in production.

Generative AI was used throughout the project for design suggestions, troubleshooting, code and command drafting, and documentation support. I did not treat AI output as authoritative. Several suggestions required correction after comparison with the real repository or live environment, including Jenkins stage wording, runtime compatibility, pod verification, and repository artifact cleanup. I documented these cases in the AI governance log and validated changes using tests, security audits, Terraform validation, Ansible checks, Kubernetes commands, Jenkins runs, and Git reviews before accepting them.

One capstone requirement I could not complete was formal peer review because no peer reviewer was available during the project period. I chose not to manufacture feedback or represent AI/self-review as peer feedback. Instead, I relied on automated validation, pull requests, security checks, deployment evidence, and repeated technical audits, and I have disclosed this limitation transparently.

Overall, the capstone improved my understanding of DevOps as a controlled delivery system. The project now demonstrates infrastructure as code, configuration management, CI/CD, security gates, monitoring, manual production governance, rollback capability, environment separation, and event-driven cloud integration. If I extended the solution further, I would move the workloads to a managed Kubernetes platform, replace long-lived AWS credentials with workload identity, use a secure remote Terraform backend, and expand monitoring into centralized metrics and dashboards.
